# Agent Note: 带精选组合能力的 Desktop 插件中心

Status: proposed

[English](2026-08-15-desktop-plugin-center.md) | 中文

## 问题

DeepSeek Harness 已能通过 npm 包、有序 Bundle patch、Cordis 插件、Host Loader 条目和客户端模块组合能力，但这种扩展性目前是开发者机制，而不是 Desktop 产品。用户必须理解包管理器命令、所选 Profile、Bundle 对账、兼容性和运行态清单，才能添加或移除能力。现有插件清单只读且面向诊断，也没有可信远程目录拥有已评审元数据、精选位、当前热度或精确版本资格。

只在渲染器里放一个目录页面无法关闭这个缺口。安装 Bundle 会修改运行中 Host 使用的文件，包变更前通常必须停止当前 Host。位于该 Host 内的服务无法监督自身替换，也无法在下一次普通启动前恢复崩溃。HTTP 请求成功、包管理器退出或静态已安装卡片，都无法证明新 Host 和客户端贡献已经激活。

因此，产品需要一个连贯能力，贯穿发现、兼容性、变更、重启、运行态验证、恢复、已安装管理和目录运营，同时保留 Harness 现有插件格式以及当前配置/诊断入口。

## 提案

按照已确认的 [PRD](../../../../docs/PRD.md)、[产品级合同](../../../../docs/specs/product-spec.md)、[Feature Map](../../../../docs/specs/feature-map.md) 和[技术架构](../../../../docs/architecture/plugin-center.md)，把精选插件中心构建为原生 Desktop 能力。

渲染器使用普通 Harness 客户端插件贡献插件中心页面和已安装管理器。Electron 主进程会成为持久本地控制面，因为它能在受控 Host 替换期间存活：它负责固定桥接方法、可信解析、单一串行操作、Profile 锁、完整变更前快照、内置精确包管理器调用、Host 代次重启、渲染器重连、运行态验证、提交和恢复。Host 现有 Loader 清单继续作为运行态证据，而不是变更权限源。

独立的 TypeScript Fastify/PostgreSQL Registry 负责目录元数据、已评审不可变精确版本、审核、精选位、隐私受限安装结果和确定性排行快照。所选 Desktop Profile 与 lock 状态继续作为本地安装事实；Loader 和客户端模块证据继续作为运行态事实。已安装视图只连接这些权限源，不创建另一个本地市场数据库。

V1 普通安装只接受固定 Registry/制品源中经过评审的预构建精确包版本。不运行生命周期脚本，也不接受渲染器提供的任意 npm、Git、URL、路径、可执行文件、argv、环境、registry 或版本范围。Desktop 内置仓库固定的 `pnpm@11.7.0` 运行时，使受支持的干净机器无需系统 Node 或 pnpm。权限/风险标签描述已评审权限，但不声称进程隔离；已安装 Harness 插件仍具有广泛的 Host 级 Node 权限。

已实现的 F002 内核在 bridge 联调前冻结了这条边界。兼容性指纹把一个确定动作绑定到 Desktop/DSH/Node 版本、平台、目录 ETag、Profile 修订、已安装投影、受保护身份与当前操作状态。受保护包和 Loader 行身份从随应用发布的 Bundle manifest 与 patch 行派生，而不在客户端维护手写列表。语义范围使用维护中的 `semver` 实现；制品校验使用维护中的 `tar` 解析器检查压缩字节、原始归档路径、包身份、Bundle 声明、被禁生命周期脚本和 `dsh.pluginCenter` 预期证据声明，全程不解压落地、不 import，也不执行插件代码。

操作采用一个持久状态机。它在写入前快照完整的变更所有权 Profile 闭包，在明确操作所有权下停止 Host，变更精确包和 Bundle 状态，启动新 Host 代次，发布移动的 loopback origin，重连现有窗口，并验证版本声明的 Host/客户端证据。只有此后才能提交。任何提交前错误或被中断日志都要在普通启动前恢复并验证旧组合，否则进入独立的恢复失败状态并提供重试和脱敏诊断导出。

手动市场、安全、事务、恢复、管理与生产 Registry 完成后，最后一个 Agent 辅助获取 Feature 允许用户明确要求 Desktop Agent 查找并安装某项能力。Agent 只搜索已验证目录，解释一个确定候选，不提交包来源权威。按代认证的封闭通道让 Electron 在当前 Agent 轮次和 Host 代次结束前持久接受并重新解析确定操作；随后 Electron 拥有普通重启、验证、回滚与恢复路径。仅推荐、存在实质歧义、不安全或无匹配请求不修改 Profile。

V1 提供一个插件中心入口、搜索、精选、本周热门、最近更新、精确插件详情、兼容/风险预检、一键安装，以及能够诚实展示系统、目录和未知本地插件的已安装管理器。现有插件配置卡和高级 Loader 清单仍可到达。技能、团队/私有范围、公开自助发布、支付、Linux 变更、任意开发者来源和视觉自由 Bundle 排序不显示空占位，而是明确不在 V1 中。

实现遵循 Feature Map 发布顺序：F001 目录发现、F002 兼容/风险预检、F003 可信安装、F005 事务/崩溃恢复、F004 已安装组合管理、F006 生产目录运营/排行，最后是 F007 Agent 辅助插件获取。尽管数字更靠后，F005 仍有意先于更广的 F004 变更集合完成；F007 明确等待全部前序权威，不改变 F001 当前优先级。

## 所有权与不变量

| 关注点 | 权限源 | 必须满足的不变量 |
|---|---|---|
| 目录身份、资格、审核、排行 | 远程 Registry | 已评审不可变精确版本；撤回只改变资格，不改变本地状态 |
| 已安装包、lock、启用/禁用有序 Bundle | 所选 Desktop Profile | 不建第二套已安装数据库；每次变更串行且可恢复 |
| Host/客户端激活 | 当前 Host 代次与客户端模块发现 | `running` 需要当前预期证据，而非包管理器结果 |
| 变更与恢复 | Electron 主进程 | 渲染器只提交闭集意图；Host 重启不能销毁操作所有权 |
| Agent 辅助获取 | Agent 工具负责搜索/解释；Electron 负责授权与变更 | Agent 只选择已验证确定 id；Electron 在替换 Host 前确认持久操作 |
| 插件配置与高级诊断 | 现有所有者客户端包 | 插件中心只链接/组合，不重复或隐藏其行为 |

固定 bridge 和共享合同使用 JSON 兼容值与稳定原因码。当前 Host origin 是代次拥有的动态状态，每个导航/发送者检查都跟随它。内置身份可见且受保护。未知本地插件保持可见，但市场只读。配置默认保留；单独确认的自有数据移除仅限明确插件自有相对路径，绝不能指向会话、工作区、凭据、共享配置或未声明文件。

精选来自编辑运营，最近更新来自可用发布时间，热门是已验证成功安装、短期动量、增长、新鲜度和回滚/激活失败惩罚的带时间戳确定性聚合。原始点击、GitHub star、运营测试事件、无效/异常事件和敏感本地内容不提供正向排行权限。

## 考虑过的替代方案

**复制 Codex Desktop 插件市场 UI 和架构。** 引用的开源 Codex 仓库提供有价值的插件管理器、目录、存储和 app-server 协议模式，但没有公开闭源 Desktop 市场实现，而 Harness 已有不同的 Bundle、客户端模块、Profile、Loader 和 Host 生命周期合同。本提案适配产品边界，而不假装两套代码可直接互换。

**把目录和变更逻辑全部放进 Host Typert Remote。** 该服务会在它需要监督的 Host 重启期间消失，也无法在普通启动前恢复中断变更。Host 继续提供只读运行态证据，Electron 负责持久性和替换。

**构建独立 Web 市场并 shell 调用 `dsh plugin`。** 这会重复 Desktop 主题、导航、已安装状态、bridge 安全和生命周期，同时仍依赖 PATH pnpm 与 CLI 私有对账；也无法提供可信的重启、重连与恢复闭环。

**在 V1 允许任意 npm、Git、URL 或本地路径。** 这会把包准备、生命周期脚本、命令、origin、可复现性和支持风险扩展到面向学员/普通用户产品之外。开发者 CLI 流程仍在普通市场之外可用。

**维护本地 SQLite 已安装插件数据库。** 任何重复记录都可能与 Profile manifest、lockfile、启用/禁用 Bundle 组合和 Loader 运行态漂移。因此已安装状态只从现有权限源派生。

**把 manifest 权限视为沙箱。** Harness 插件在进程内以广泛权限运行。评审元数据与风险披露能减少供应链不确定性，但无法诚实保证隔离，所以 V1 不作隔离承诺。

**与插件一起发布技能、团队/私有范围和公开发布。** 这些模式拥有不同身份、策略和生命周期合同，会拖延第一个完整插件旅程。它们被延期，也不显示为空 UI。

**让 Agent 搜索 GitHub/npm 并安装它任意选择的内容。** 这会绕过已审核确定版本权威、兼容证据、生命周期脚本策略与确定恢复。外部仓库最多只能成为未来运营审核输入，不能授予安装权威。

**让 Agent 工具或 Host 拥有安装事务。** 工具运行在安装操作必须替换的 Host 代次里，因此会在自己的操作期间消失。Electron 必须在静默前持久确认请求，并保持唯一事务所有者。

## 验收标准

- 在没有系统 pnpm 的干净打包 macOS arm64 与 Windows x64 机器上，用户选择一个兼容且已评审的精确夹具，看到预检和有序进度，Desktop 窗口在 Host 重启/重连期间保持，声明的 Host/客户端能力可见，并在完整重启后仍保持激活。
- 不兼容、被篡改、任意来源、受保护组件、路径穿越、生命周期脚本和渲染器越权尝试都在 Profile 变更前失败，权限源哈希不变，并提供可执行产品语言原因。
- 安装、启用、禁用、更新和卸载的每个提交前阶段都有确定性故障注入；每个用例要么恢复并验证旧组合，要么可见地结束为 `recovery-failed`。变更期间杀死 Desktop、恢复期间再次杀死，仍通过启动恢复收敛。
- 已安装管理显示系统、目录、已禁用、失败和未知本地状态，不隐藏现有配置卡或高级运行态清单。启用/禁用/更新/卸载在重启后保持，普通卸载保留配置。
- 已认证运营人员可以发布/评审一个不可变精确版本、将其精选、生成可审计最近/热门快照并撤回，无需发布 Desktop 新版本。撤回阻止新安装，但不静默改变现有本地 Profile。
- 事件摄取保持幂等并拒绝未知或敏感字段。精选、热门和最近更新保持不同语义；Registry 失败时保留明确标记过期的最近已验证缓存，而不是授予未知安装权限。
- F001–F006 通过后，一条明确自然语言“查找并安装”请求产生一个有解释的确定已审核候选，并在 Host 停止前产生一个 Electron 操作 id；同一操作跨重连存活、验证真实能力并在重启后保持。仅推荐、歧义、无匹配、任意来源、过期/重放与拒绝场景给出聚焦结果，Profile 哈希保持不变。
- 静态 UI、HTTP 200、包管理器退出、构建成功或截图都不能单独满足验收；证据必须包含选择/输入、触发、进度/状态变化、当前运行结果，以及持久性或已验证恢复。

## 风险

核心风险是供应链权限：精选插件仍具有广泛 Host 级 Node 访问。评审、精确制品、摘要、固定 origin、不运行生命周期脚本、受保护身份和透明风险语言可以降低暴露面，但不能消除恶意运行态行为。强隔离需要独立架构提案。

Host 替换和跨平台包变更容易失败，尤其涉及移动 origin、旧子进程退出、Windows 已加载文件、进程崩溃和改变兼容性的应用更新。即使成功路径更早可用，也必须通过代次测试、完整快照、逐阶段故障注入、真实运行态验证和两个打包平台后才能解除发布闸门。

Registry 增加一套运营服务、PostgreSQL 迁移、对象存储、审核、隐私处理和排行对抗压力。V1 有意接受内部运营工具与确定性非个性化排行，而不增加公开门户或推荐系统。Registry 不可用时，发现内容可以过期，但本地安装/运行态事实必须继续可用且诚实。

Agent 选择会增加模型与生命周期风险：模型可能偏好不合适候选、从推荐请求推断授权、通过搜索泄露本地上下文，或在 Host 重启时丢失工具结果。因此 F007 保持最后，使用确定性无密钥行为快照和真实 Desktop 验收，限制 Registry 查询，在存在实质歧义时聚焦确认，并让 Electron 在 Agent 轮次结束前持久化且确认确定操作。

这些文档冻结的是架构审计基线，并不承诺上游 API 永不变化。实现若要改变固定 DeepSeek Harness/Codex 来源的接口，开发者必须先刷新对应的窄范围源码审计并更新治理合同，而不是凭假设增加兼容层。
