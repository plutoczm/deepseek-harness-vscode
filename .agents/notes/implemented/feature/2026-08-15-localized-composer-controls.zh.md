# Agent Note: 本地化编辑器权限与 DeepSeek 控件

Status: implemented

[English](2026-08-15-localized-composer-controls.md) | 中文

## 问题

中文编辑器仍把内置权限预设显示为 `Read Only`、`Workspace Write` 和 `Full access`。模型控件也把 DeepSeek 的适配器取值显示成通用的 `Effort: High`。这让已本地化的产品显得不完整，也容易被理解成 Codex 风格的速度控制，但 Harness 的 DeepSeek 适配器实际提供的是思考选项，而不是速度。

## 决策

**内置权限标签归 locale 字典所有。** 编辑器 chip、当前会话的 `/permission` 选择器和「通用设置」中的默认权限选择器，都通过各自持有的 locale 命名空间渲染 `read-only`、`workspace-write` 与 `danger-full-access`。中文标签为「只读」「工作区写入」「完全访问」；英文保留既有产品文案。三个 id 之外的 host 自定义名称保持原样。命令行、投影值、设置值与完全访问风险确认仍使用既有机器 id。

**DeepSeek 推理元数据显示为思考模式。** 当前所选提供方为 DeepSeek 时，编辑器把推理行称为「思考模式」，并将适配器的 `off`、`high` 与 `max` id 本地化为「关闭思考」「深度思考」和「最大思考」。英文对应 Thinking off、Deep thinking 与 Maximum thinking。适配器提供的说明仍然优先；缺少说明时由客户端补充简短的 DeepSeek 解释。其他提供方继续显示其适配器持有的强度名称和通用推理标签。

**编辑器只公开适配器已经持有的请求级设置。** 选择 DeepSeek 思考选项时，仍通过 `session.selectModel` 提交既有 `reasoningEffort` 字段。端点、凭据、上下文容量、输出上限、超时、重试与模型目录配置继续留在既有 DeepSeek 设置界面；不引入虚构的速度值或新 wire 字段。

**控件布局遵循已成熟的侧边菜单交互。** 「模型」与「思考模式」行保持可见，鼠标悬浮、键盘聚焦或点击后，匹配的选择卡从右侧展开。一层不可见的指针桥接填满 8px 的视觉间隙，240ms 的离开宽限会在指针穿越期间保持侧卡挂载；进入任一张卡都会取消待执行的关闭。权限卡增加 DeepSeek Harness 标题、简短后果说明、尾部选中对勾，并对「完全访问」使用风险色强调。这些展示变更继续复用既有选择命令与完全访问确认闸门。

## 曾考虑的替代方案

**为 DeepSeek 移除推理行。** 不采用：已交付的 DeepSeek 适配器明确公布 `off`、`high` 与 `max`，移除该行会隐藏真实的单次请求能力。

**仿照其他编程客户端增加速度选择器。** 不采用：DeepSeek Harness 没有可读取或提交的速度契约。只存在于展示层的选择器会宣称提供方链路无法兑现的行为。

**翻译所有 host 提供的权限或推理名称。** 不采用：部署可以定义自有取值，其标签属于权威数据。本地化只覆盖仓库持有语义的内置权限 id 与 DeepSeek id。

## 后果

中文桌面会话现在显示完整的中文权限菜单和 DeepSeek 专用的悬浮侧边思考菜单，同时不改变持久化状态或后端协议。侧卡在正常鼠标移动速度下仍可选择，模型 A → B → A 的切换会经过同一条稳定路径。英文行为与自定义提供方标签仍然可用，通用模型提供方继续渲染自己的元数据。可见控件获得定向组件与浏览器覆盖；实现接受 client 包隔离规则所要求的少量 locale 词汇重复。
