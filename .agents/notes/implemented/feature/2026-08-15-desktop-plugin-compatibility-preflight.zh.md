# Agent Note: Desktop 插件兼容预检

Status: implemented

[English](2026-08-15-desktop-plugin-compatibility-preflight.md) | 中文

## 问题

目录发现能够标识一个已审核确定版本，但不能证明某个动作适合当前应用、运行时、平台、Profile 组合或目录修订。若允许渲染器提交包身份、制品证据、环境事实或策略，展示输入就会变成安装权威。目录或 Profile 改变后继续复用旧决定也存在同样缺陷。兼容性还需要展示可理解的负向结果，同时不能让 F002 获得下载、改变 Profile 或重启 Host 的权限。

## 决策

**一个兼容决定只属于一个确定的 Desktop 自有指纹和一个渲染器意图。** 渲染器只提交 `pluginId`、确定 `version` 与封闭 `action`。固定 preload 方法通过既有当前窗口与 origin 检查转发该值。Desktop 每次请求都会解析确定可信目录预检，重新构建当前 Desktop/DSH/Node/平台/目录新鲜度/Profile/受保护身份事实，并返回有序 `CompatibilityDecision`。未知字段、确定版本位置中的范围、包名、URL、路径、制品证据、环境事实和策略值都会在桥接合同处失败。

**目录在渲染器安全详情旁保存私有预检权威。** 每个已解码快照必须为每份确定详情包含一个确定 `CatalogVersionPreflight`。快照解码要求两者的 ETag、审核、资格、下架、风险、能力与预期运行证据一致。列表和详情投影绝不返回包身份、语义版本范围、制品 URL、摘要、冲突或支持动作策略；`CatalogRepository.resolvePreflight()` 是仅限 Desktop 的查询。

**所选 Profile 投影从持久文件重新生成，未知 Bundle 不会获得目录身份。** Desktop 读取 Profile manifest、用户 patch、锁文件、依赖 Bundle manifest 与 Bundle patch；它派生启用顺序和 Loader id，并把每份已消费权威文件哈希进 `profileRevision`。只有包名与确定版本同时匹配一份可信目录预检时，已安装包才映射到插件 id。未知本地 Bundle 保留 `pluginId: null`，因此包身份不能冒充目录审核。受保护包与 Loader 身份来自随应用发布的 Bundle 组合，不由客户端维护手工允许列表。

**拒绝是普通的只读产品结果。** 目录审核、下架、新鲜度、发布范围、平台制品、证据完整性、受保护身份、已安装碰撞、声明冲突、当前操作状态与动作状态都会产生稳定有序原因。客户端展示允许与拒绝状态、当前指纹事实、重启预期、能力、风险和广泛应用权限告警。“安装”用于说明方向但保持禁用；F002 没有变更桥接。

**制品校验不执行代码，并留在 Desktop 权威之后。** 校验器消费可信确定版本证据，以及后续受控下载代码提供的归档字节。它限制压缩与解压内容、校验摘要与身份、拒绝不安全路径和链接、禁止生命周期脚本，并在不导入或执行插件代码的情况下检查 Bundle 与运行证据声明。结果只包含原因和观察到的身份，不包含归档字节或本地路径。

**浏览器开发使用确定决定，不获得本地权威。** `dev:desktop:web` 复用生产客户端组件，并提供允许、陈旧、明确拒绝、空与错误场景。它不读取用户 Profile，也不获得 Electron、文件系统、包管理器、MCP 或 Host 重启权限。

## 曾考虑的替代方案

**接受渲染器提供的环境或制品字段。** 不采用：受损渲染器可以自行选择用于批准自身请求的证据。

**把 F001 兼容摘要当作动作决定。** 不采用：发现摘要不绑定动作、当前 Profile 修订、受保护组合、目录新鲜度或已安装冲突。

**缓存一次允许决定供后续事务使用。** 不采用：目录 ETag、Profile 文件、运行版本、操作归属或所选动作都可能改变。后续事务必须重新解析确定版本，并针对当前事实重算。

**在恢复链路未完成时开放可用“安装”按钮。** 不采用：允许兼容决定不等于包事务、激活证明或回滚保证。禁用状态可以说明结果，而不会宣传尚未实现的生命周期。

**让浏览器开发桥接访问真实 Profile。** 不采用：Web 通道用于快速 UI 与状态验收；系统权威属于 Electron，并需要独立 Desktop 验收。

## 验证

合同与 Desktop 测试覆盖严格目录/预检配对、确定渲染器意图、当前发布与受保护身份、语义版本与动作矩阵、未知本地 Bundle 投影、陈旧目录拒绝、归档安全和桥接归属。无 Key 预检集成套件针对临时 Profile 执行 17 项元数据拒绝和 15 项制品拒绝，并证明 Profile manifest、锁文件、Bundle 顺序、Host 代次与已安装投影的前后哈希一致。客户端测试和构建 Bundle 回放覆盖允许、有序拒绝、失败、广泛权限、禁用动作、返回、陈旧缓存、会话与保留设置旅程。局部类型与 Bundle 检查通过；本次实现没有构建 Electron，也没有生成 Desktop 包。

## 后果

F002 提供可见的兼容与风险结果，同时没有创建第二个安装拥有者，也没有改变本地状态。F003 可以消费相同的确定版本目录查询、新鲜指纹、原因词汇与制品校验器，但必须在变更前重新计算，并继续负责受控下载与事务机制。F004 为已安装状态动作复用这些语义，F005 仍是使这些动作可达的条件。代价是“安装”控件有意保持禁用，并需要独立 Desktop 验收 preload、打包 manifest 路径与真实当前 Profile 事实。
