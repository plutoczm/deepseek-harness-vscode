# Agent Note: Desktop 已安装组合管理

Status: implemented

[English](2026-08-15-desktop-installed-composition-management.md) | 中文

## 问题

已安装包、活动 Bundle 与可观察运行能力是不同事实。若管理页面保存自己的已安装数据库，或把包管理器成功等同于激活，就会与 Profile 和 Host 漂移。更新与卸载还跨越已加载进程和破坏性数据边界；应用升级时，一个不兼容外部 Bundle 也不能阻止整个 Host 启动。

## 决策

**已安装视图只从现有权威重建。** Desktop 连接 Profile 依赖 manifest、活动与停用 Bundle 顺序、确定已安装包 manifest、已验证目录缓存、发行版保护身份、当前操作日志，以及 Host/客户端/Skill 运行证据。系统、目录归属和未匹配本地条目保持区分。配置与高级运行清单继续由设置持有，插件中心只导航到原入口，不复制实现。

**所有受支持生命周期动作复用一个事务拥有者。** 启用与停用把包原子移动到有序 `bundles` 或 `disabledBundles`；更新在保留该意图的同时替换一个已审核确定版本；卸载在删除包前停止 Host，并移除依赖与两处 Bundle 成员。每个动作都复用现有锁、快照、日志、Host 替换、健康检查、运行转换证据、提交标记和恢复交接。

**运行连续性只比较能跨 Host 换代保持的身份。** `include:agent-presets:` 下的 Loader 子项属于实时预设实例，在会话恢复前可以不存在，因此变更连续性与恢复比较会排除它们。候选项声明的 Loader 条目、客户端模块和 Skill id 仍须精确满足；其 `agent-presets` 所有者行与其他全部无关运行身份必须保持存在。

**插件自有数据属于第二次破坏性决定。** 卸载始终保留配置和数据。确定包仍存在时，Desktop 把其有界相对路径声明绑定到卸载操作。只有匹配的已提交卸载加独立固定确认，才能删除产品归属插件存储根下选中的声明。路径穿越、未声明路径、重叠选择、符号链接、系统身份和本地身份都会被拒绝。

**数据决定可以跨 Host 与 renderer 换代恢复。** 卸载提交后，动态 Host origin 会销毁旧页面状态，因此 Desktop 以当前已提交日志和 operation 绑定的 authority 重新投影一次数据 offer。用户明确保留或完成选择性删除后，Desktop 只消费该 offer 元数据；未选择的数据和配置保持不变，完整重启也不会重复弹出。

**应用兼容在普通 Host 组合前核对。** 若一个已审核外部 Bundle 的确定版本与当前 Desktop、DSH、Node、平台、制品证据或已安装组合冲突，它会在 Host 启动前进入 `disabledBundles`。包、原停用意图、系统组件和未匹配本地 Bundle 保持不变。已安装投影派生相同原因码，并在恢复兼容前不提供启用。

生产 preload 已用 `mutationsEnabled=true` 开放这些动作；未解决的恢复失败仍会通过同一恢复控制器关闭新变更。

## 考虑过的替代方案

**在插件中心数据库中保存已安装状态。** 拒绝，因为 Profile、包、日志和运行事实都可能在页面之外变化。

**把配置或缓存删除折叠进卸载。** 拒绝，因为包归属不授予删除用户数据、凭证、工作区或共享配置的权力。

**先启动 Host，再停用不兼容 Bundle。** 拒绝，因为不兼容代码可能在管理界面出现前就让组合失败。

**先等待 renderer 重建实时预设实例，再核对运行证据。** 拒绝，因为恢复会在 renderer 重载前验证，而会话是否存在并不是恢复后 Profile 的确定属性。

## 验证

局部合同与测试覆盖来源分类、明确停用 Profile 状态、保留设置入口、确定更新选择、每个动作前确认、启停运行转换、活动与停用更新意图、卸载后配置不变、绑定已提交操作的自有数据删除、路径穿越与符号链接拒绝、应用升级前停用、重启持久、换代时预设实例消失，以及 Windows 包变更只在 Host 释放已加载文件后执行。真实 Desktop 验收还验证了真实 Host 的 `include:`/`module:` 证据身份、系统显式禁用 Loader 行、pnpm 11 的 remove 参数，以及 Host 换代后的数据 offer 恢复。相关局部测试、合同生成、Desktop 类型检查、插件中心客户端 Bundle 和未签名 macOS arm64 目录包构建通过。

早期 `/tmp` 包体验收曾把管理控制器接到隔离 Profile，并在 PATH 不含系统 Node/pnpm 时通过真实停用/启用、卸载、Host 换代、默认数据保留、选择性删除和完整退出重启；系统与 Skill Pack 运行证据保持健康。生产现已开放该控制器。本轮 macOS 源码验收没有覆盖真实跨版本更新、应用升级停用和 Windows 已加载文件行为。

## 结果

目录发现不能获得已安装状态所有权。重新安装可以发现保留配置和数据，但任何生命周期动作都不会静默重新启用因应用兼容而停用的 Bundle。运行比较放弃实时预设实例子项的精确连续性，同时保留确定目标证据和稳定无关身份的严格核对。恢复失败会关闭新变更，直到既有恢复流程成功。
