# Agent Note: Desktop 插件发现页面

Status: implemented

[English](2026-08-16-desktop-plugin-discovery-page.md) | 中文

## Problem

插件中心同时承载目录浏览、已安装包管理、兼容性说明、恢复提示与生命周期动作。随着公开目录增长，用户需要更快地查看当前推荐和最近新增条目，同时不能继续增加管理页面的密度，也不能削弱其操作职责。

## Decision

Desktop 客户端在 `sidebar.primary.action` 中将 `plugin-discovery` 注册在 `plugin-center` 之后，并为其提供独立的 keyed `main.page`。插件发现通过同一个 Desktop 桥接消费现有公开插件目录和已安装投影；它不增加包来源、目录权限或变更路径。

概览保留目录由服务端拥有的精选、热门与最近更新顺序。页面展示一张精选卡片、紧凑热门排行、最近更新卡片、搜索，以及仅与返回的已审核元数据匹配的能力分类。客户端不计算热门分数，不把“最近更新”改写为保证当天发布，也不会在没有可审计目录字段时展示增长数字。

同一页面提供“让 Agent 找插件”子功能，而不增加第三个一级入口。用户提交自然语言需求后，当前会话确定性调用标准预设内置的 `find-plugins` Skill；该 Skill 标记为仅用户调用，因此不会向每个普通回合发布常驻 Skill 目录。Skill 通过有界只读脚本搜索公开 npm `dsh-plugin` 目录，过滤出声明 Bundle patch 与不可变分发证据的确定版本，并要求 Agent 只基于返回元数据推荐最多五项。缺少 DeepSeek 凭据时，客户端先打开现有模型设置且不发送对话。推荐只回到当前对话，不绕过插件中心安装权威。

客户端贡献会显式注入 Conversation 服务，并在发送前通过 `sessions.scope(sessionId).get('conversation')` 解析当前会话的作用域服务面；它不依赖未声明的 Context 快捷属性，因此打包后的 Cordis 运行时与测试桩会走同一条服务路径。

打开条目时保留发现位置，并展示右侧确定版本面板。面板读取现有详情和兼容性决定；安装继续使用现有兼容检查、对广泛权限的明确确认、只含不可变插件 id 和版本的意图，以及操作进度对话框。已安装条目会打开插件中心进行管理，而不会重复提供启用、停用、更新或卸载控制。

## Interaction ownership

插件发现拥有搜索文字、Agent 查找需求、所选视图、能力分类、所选详情与面板局部焦点。Agent 会话拥有自然语言理解与推荐文本，公开 npm 目录拥有候选元数据。Desktop 目录拥有可安装成员和顺序，兼容桥接拥有安装资格，操作桥接拥有进度，插件中心仍是唯一的已安装组合管理器。

## Alternatives considered

**在插件中心增加另一个分区。** 这种方式只保留一个入口，但会让发现功能与已安装状态、恢复、配置和生命周期动作在已经密集的页面中竞争。

**展示客户端计算的增长和下载指标。** 当前摘要没有可审计的时间序列证据，因此推导或装饰性数字会错误表达目录事实。

**复制公开导航站的落地页。** 大型营销标题和分类宫格会低效占用桌面空间，并破坏现有 Harness 导航与卡片密度。

**为 Agent 查找再增加一个一级页面。** 该任务仍属于插件发现；独立页面会重复目录上下文，并让用户在“发现”和“查找”两个近义入口之间选择。

**让 Agent 直接安装推荐项。** 推荐基于不可信公开元数据，不能替代确定版本兼容检查、权限确认和现有受信任变更链路。

**把查找 Skill 公布到每个 Agent 回合。** 这会让未使用该功能的普通对话也携带 Skill 目录和上下文记录；显式按钮已经提供确定入口，因此没有必要支付常驻提示词成本。

## Consequences

用户既能浏览目录，也能用一句需求让 Agent 缩小候选范围，同时每次安装仍然经过受信任的 Desktop 路径。代价是主动查找会增加一个模型回合和一次公开目录查询；没有满足安装元数据要求的候选时，Agent 必须明确返回无结果。页面只能展示当前目录元数据支持的排行含义和分类；未来的增长视图必须先增加目录合同和后端证据，UI 才能加入。
