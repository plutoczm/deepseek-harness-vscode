# Pet 插件第一支录制计划

## 模式与成片

- 录制模式：`described-operation`
- 确认模式：`standalone-staged`
- 当前状态：用户已确认，进入预演与录制
- 画面：真实 Electron Desktop，1920×1080、16:9、30 fps、H.264
- 风格：纯净画面，无字幕、无音频；保留鼠标移动和点击波纹
- 第一版：先出无放大的素版；用户看过后再决定是否对安装按钮、Pet 面板和启停状态加局部放大

## 唯一录制段：Pet 完整生命周期

关联 Feature：`F003-trusted-installation`、`F004-installed-composition-management`。

镜头顺序：

1. 从真实 Desktop 插件中心开始，基线为 Pet 未安装、屏幕上没有 Pet。
2. 在搜索框输入 `mypet`，展示 npm 公开目录中的 `mypet@1.0.7`。
3. 点击“安装”，勾选信任确认并执行真实安装。
4. 展示受信安装进度和 Host 自动重连；等待 Pet 悬浮在桌面应用内。
5. 通过首次领养选择“豆豆 / 小狐狸”，执行一次“抚摸”，展示真实互动反馈与状态变化。
6. 打开“已安装”管理，停用 `mypet`；等待事务完成并展示 Pet 消失、包仍保留。
7. 在同一管理行重新启用 `mypet`；等待事务完成并展示 Pet 返回。
8. 由于 Desktop Host 重启会更换 loopback origin，Pet 的端口级 `localStorage` 会再次进入领养态；真实完成同一领养后，以“已启用 / 运行中 + 可互动 Pet”作为结束镜头。

## 真实结果证据

- 模式：`live-result`，不使用 mock 或静态替身。
- 主证据键：`pet-runtime-presence`。
- 安装前 Pet 运行节点数量为 0；安装后变为 1；停用后回到 0；启用后再次变为 1。
- 辅助证据：已安装投影在停用和启用后分别显示“已停用 / 未运行”和“已启用 / 运行中”。

## 预演、测试数据与复位

- 当前真实基线：预演已完成，`mypet` 已卸载且屏幕上没有 Pet。
- 预演真实通过安装、首次领养（名称“豆豆”、皮肤“小狐狸”）、互动、停用、启用和卸载复位。
- Pet 使用按 origin 隔离的 `localStorage`，而 Desktop 每次 Host 重启会更换端口；因此正式镜头如实展示安装后和重新启用后的领养，不伪造跨端口档案。
- 正式录制终态：`mypet@1.0.7` 保持已安装、已启用，宠物档案保留。
- 副作用：仅修改本机 Desktop 的 `web` Profile 与 `mypet` 本地浏览器数据，可随时卸载；不触发外部账号、付费或第三方写入。

## 不录内容

- 不录卸载，因为用户本次明确要看安装、运行结果以及开启/停用；卸载会破坏最终展示状态。
- 不录其他插件，先只交付 Pet 第一支供用户验收。

## 风险与处理

- npm 下载和 Host 重连时间不固定：保留真实状态变化，成片只剪除无信息的静止等待。
- Host 重连会改变内部端口：录制控制需自动重新绑定当前 Electron 页面。
- Pet 插件 UI 缺少测试 ID：固定 `mypet@1.0.7`，预演逐项验证选择器与可见结果后才录素版。
